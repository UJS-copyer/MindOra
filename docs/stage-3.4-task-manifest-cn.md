# Stage 3.4 阶段文档：公开问答闭环与流式交互（Public Q&A & Streaming）

> 一句话用途：记录 Stage 3.4 打通前台公开免登录问答、SSE 打字机流式出字与章节级引用回链的 Spec 设计目标与实现交付情况。  
> 维护日期：2026-10-17　状态：**已完成**

---

## 1. Spec 设计目标

Stage 3.3 完成了后端的问答生成链路，但仅限管理端内部测试使用。本阶段旨在将问答能力安全、平滑地推向**前台公开网站**，让外部访客直接可用，并提供流畅的现代对话体验：

1. **公开端点与严格安全边界**：提供面向前台访客的公开问答接口，免去复杂登录门槛；服务端严格强制将检索范围锁死在公开已发布的文章内容上，任何私有笔记一律不可被检索，杜绝数据外泄。
2. **防刷限流与密钥安全防护**：对公开问答接入 Redis 固定窗口限流，防止外部恶意高频刷爆 API；增加敏感信息过滤（SecretGuard），如果检索到的正文中意外包含密钥或私密配置，自动阻断并拒绝输出。
3. **SSE 打字机流式交互**：后端采用 SSE（Server-Sent Events）协议实现增量流式推送，前端像 ChatGPT 一样逐字打字机式出字，大幅缩短用户的首字等待感知时间。
4. **前台问答页面（`/chat`）上线**：在前台博客网站提供专属的 AI 问答界面，交互简洁流畅，支持随时停止生成。
5. **章节级引用跳转回链**：模型回答完毕后，展示清晰的引用来源卡片；用户点击卡片后，能够直接跳转回原博客对应的章节锚点（`/blog/{slug}#h={anchor}`），让答案有据可查、随时验证。
6. **完善的异常状态处理**：当遇到知识库外的问题时友好拒绝回答；当触发频率限制时显示冷却倒计时；当后台大模型故障时提供降级解释，杜绝白屏或直接报错。

---

## 2. 实现情况

本阶段所有核心目标已全部达成，前后端代码已通过自动化测试与真实浏览器端到端验收：

1. **公开端点与限流保护交付**：后端上线 `/api/v1/public/rag/answer` 与流式端点 `/stream`；检索范围由服务端写死为 `scope=public`，实测私有笔记召回率为 0；基于 Redis 实现了匿名 IP 每分钟限流，超限时返回标准的 429 提示。
2. **敏感信息安全过滤落地**：开发了 SecretGuard 过滤器与语料凭据扫描工具（`scripts/security/scan-corpus-secrets.mjs`），实测公开暴露面为 0 泄漏，并在流式传输过程中提供实时脱敏兜底。
3. **SSE 流式与事件契约通畅**：打通了增量出字（`delta`）、逐条引用卡片（`citation`）到最终结束（`done`）的完整流式事件链；首字响应时间稳定在 2~3 秒左右，支持中途主动停止生成。
4. **前台问答页面正式发布**：前台网站上线 `/chat` 界面，全套单测通过，生产打包正常；在真实 Chromium 浏览器中实测正向提问、打字机流式、引用卡片点击定位原文章节、拒答文案替换以及冷却倒计时均完美闭环。
5. **修复引用回链缺陷**：解决了此前文章链接标识（slug）在知识库中未持久化导致的无法跳转问题，在数据库中增加了专用持久化字段并完成迁移回补。

---

## 3. 核心功能与接口一览

- **公开同步问答**：`POST /api/v1/public/rag/answer`，接收用户输入，一次性返回完整答案与引用。
- **公开流式问答**：`POST /api/v1/public/rag/answer/stream`，采用 SSE 方式返回打字机增量内容与终态元数据。
- **前台问答路由**：`http://localhost:5173/chat`，提供面向前台访客的交互式问答界面。

---

## 4. 关键规则与已知限制

- **服务端强制锁死公开范围**：公开问答接口的请求体中没有范围参数，服务端内部绝对写死 `public` 范围，完全不给前端留任何越权参数空间。
- **多轮会话的承接**：本阶段专注于前台单轮公开免登录问答，登录用户的多轮会话历史与记忆能力由后续 Stage 3.5 承接。
