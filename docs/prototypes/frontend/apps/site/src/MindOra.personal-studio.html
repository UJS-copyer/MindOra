MindOra 的 RAG 体系摒弃了单纯依靠单一向量相似度的粗糙方案，采用「5 步递进式混合检索流水线」：

  1. 文档解析与语义分块 (Chunking)：保留 Markdown 标题路径作为前缀上下文，杜绝代码块断裂；
  2. 双路并行检索 (Hybrid Search)：同时发起 Lucene 倒排索引与 Qdrant 1536 维 Cosine 向量检索；
  3. RRF (Reciprocal Rank Fusion) 倒数排名融合：平衡稀疏关键词命中与语义泛化召回；
  4. BGE-Large 交叉编码重排 (Rerank)：对 Top-20 候选切片进行精准语义对齐打分，取 Top-3 注入上下文；
  5. 带引用的增强生成：生成回答并强制关联真实的切片 Point ID。

在构建个人知识库或企业知识问答系统时，最容易遭遇的误区是“将全部文本一股脑切为 500 字符丢入向量数据库”。这种简化的做法在面对真实的技术笔记、代码块和跨小节上下文时，会迅速暴露出切片断裂、关键词召回无力等致命缺陷。

1. 传统向量检索的现实困境

纯向量检索依赖 Embedding 模型的全局语义对齐，但在处理具体的技术类专属术语（如 `AQS`、`epoll`、`ThreadLocal`）时，由于高维空间距离被稀释，往往难以精确召回包含精准代码实现的段落。
