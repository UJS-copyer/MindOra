构建现代化个人 RAG 系统的切片策略与重排实践

在个人知识库场景下，文档具有结构清晰、Markdown 标题层级明确的特点。本文剖析如何结合父子层级关系保持长上下文连贯性，并引入重排模型消除幻觉。

一、为什么传统的定长切片会失效？

许多通用 RAG 教程推荐使用 500-token 定长分块（Fixed-size Chunking）。但在技术笔记中，代码块、函数签名和表格会被机械切断，导致检索召回的单片碎屑无法被大语言模型完整理解。

MarkdownHeadingSplitter.ts 
export async function chunkMarkdown(content: string, options: ChunkConfig) {
  const ast = parseMarkdownToTree(content);
  // 保留全路径 Heading 作为上下文注入
  return traverseTree(ast, {
    maxTokens: 800,
    overlap: 120,
    injectHierarchy: true
  });
}

1.2 标题树父子关系递归继承

针对多级 Markdown 章节，我们将根标题与二级路径注入为每个 Chunk 的 metadata 前缀，使得向量相似度不仅匹配正文语义，更能准确锚定在所属系统模块内。

二、重排模型 (Reranker) 的实测增益

在第一阶段向量检索召回 Top-20 后，通过 SiliconFlow 托管的 BAAI/bge-reranker-v2-m3 对问题和候选文档进行交叉注意力评分，只把相关度前 3 的切片送入 Prompt。实验证明，这种组合显著降低了上下文噪音并节约了 Token 消耗。

三、落地指标与阶段总结

经过对 42 篇知识文档与 318 个向量切片的压测，结合单机 MySQL + Qdrant 运行方案，混合召回准确度达到 89.4%，完全满足个人知识检索与智能写作问答的精度需求。
