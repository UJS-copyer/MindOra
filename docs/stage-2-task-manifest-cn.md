# Stage 2 阶段文档：知识库闭环与数据同步（Knowledge Base Loop）

> 一句话用途：记录 Stage 2 知识库接入、文档解析、切片入库与向量化的 Spec 设计目标与实现交付情况。  
> 维护日期：2026-10-17　状态：**已完成**

---

## 1. Spec 设计目标

本阶段旨在建立一套完整的「知识入库与向量化处理」闭环，把私有笔记和线上文章自动处理成后续可用于 AI 问答的数据资产：

1. **多源数据接入与单向同步**：支持接入外部笔记仓库（以 Gitee 私有仓库为主），拉取 Markdown 笔记进行单向同步，严禁向远程笔记仓库反向写入任何内容。
2. **文档结构解析与切片管理**：对拉取到的 Markdown 进行分块解析（识别标题层级、段落、代码块、表格等），剥离顶部元数据（frontmatter），按合理长度切分成切片（Chunk）并记录版本。
3. **向量化处理与向量库写入**：接入向量模型（阿里百炼 text-embedding-v4），将文本切片转换为向量，并写入向量数据库 Qdrant 中存储，支持追踪索引成功与失败状态。
4. **异步调度与重试保障**：借助 RocketMQ 实现后台异步处理，同步和向量化失败时支持单独重试或全量重新索引。
5. **知识与博客内容联动**：支持将私有知识库中的任意一篇笔记一键生成为博客草稿，人工审阅发布后才对公众可见；在线发布的博客文章也能自动同步进入知识库。

---

## 2. 实现情况

本阶段所有核心功能已全部交付，并在真实环境下完成了端到端联调：

1. **Gitee 笔记仓库稳定同步**：成功打通私有仓库同步链路，能够递归扫描并拉取全部 Markdown 文件，通过 RocketMQ 异步队列稳定削峰消费。
2. **切片入库与向量化跑通**：切片数据正常存入 MySQL，并调用真实百炼向量模型完成向量化，成功写入 Qdrant 向量集合（`mindora_chunk`），单文档与批量重建索引均实测通过。
3. **后台管理界面全面上线**：后台新增知识源配置、同步任务日志、文档与切片详情、索引状态与重试操作页面，状态变更支持静默刷新。
4. **文章草稿反向生成闭环**：实测可在后台将任意知识文档生成关联草稿，保存并手动发布后前台可见，且重新发布时会自动复用知识关联，不会在库中产生重复文档。
5. **模型连通性与降级就绪**：接入了 SiliconFlow 的 Rerank 重排模型预览接口，当未配置密钥或网络异常时，系统有清晰的错误标识与重试路径。

## 3. 核心功能与操作一览

- **知识源配置**：`GET/POST/PUT /api/v1/admin/knowledge/sources`，添加并管理 Gitee 仓库地址与访问令牌。
- **触发同步**：`POST /api/v1/admin/knowledge/sources/{id}/sync`，手动发起增量或全量笔记拉取任务。
- **任务与重试**：`GET /api/v1/admin/knowledge/tasks`、`POST .../tasks/{id}/retry`，查看任务运行状态及对失败任务发起重试。
- **文档与切片管理**：`GET /api/v1/admin/knowledge/documents`，浏览入库文档，查看其切片详情与启用状态。
- **转为博客草稿**：`POST /api/v1/admin/knowledge/documents/{id}/article-draft`，把笔记一键转为后台博客草稿。
- **索引重建**：`POST /api/v1/admin/knowledge/documents/reindex`，对文档进行全量重新切片与向量入库。

---

## 4. 关键规则与已知限制

- **只读保证**：远程笔记仓库仅作为只读源，所有解析切片与元数据均保存在本地系统，绝不反写远程。
- **公开权限隔离**：从私有笔记生成的博客草稿默认仍为私有状态，只有人工在后台明确点击“发布”后，才会被标记为公开可访问。
