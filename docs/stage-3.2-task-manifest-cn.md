# Stage 3.2 阶段文档：关键词检索与混合检索融合（Hybrid & RRF Search）

> 一句话用途：记录 Stage 3.2 引入本地 Lucene 关键词检索与 RRF 双路召回融合的 Spec 设计目标与实现交付情况。  
> 维护日期：2026-10-17　状态：**已完成**

---

## 1. Spec 设计目标

单纯依赖向量检索（语义相似度）在处理精确专有名词、代码符号、具体错误码或专业术语时容易遗漏。本阶段旨在引入**关键词全文检索**并与向量检索进行**混合融合**，显著提升复杂查询下的召回质量：

1. **轻量级关键词检索**：在后端进程内直接嵌入 Lucene 引擎，中文使用 CJK 二元分词，自动拆分代码标识符；无需搭建复杂的独立搜索引擎服务。
2. **零模型成本重建**：关键词索引直接基于 MySQL 中的有效切片生成，重建过程不需要调用向量模型，不消耗任何外部 API 额度。
3. **混合检索与 RRF 融合算法**：采用业界成熟的倒数排名融合（RRF）算法，将向量检索召回的前 30 条与关键词检索召回的前 30 条自动融合，取综合排名前 20 条送入重排模型，最终输出质量最高的 8 条结果。
4. **透明化调试信息**：在后台检索调试页面展示每个结果的召回来源（是“仅向量召回”、“仅关键词召回”还是“双路同时命中”），并展示各自排名和 RRF 得分。
5. **修复权限同步漏洞**：建立「以 MySQL 为最终权限权威」的原则。文档一旦被撤回为私有，检索时无论向量库或全文索引是否更新，必须由 MySQL 最终把关，严防私有内容泄漏。

---

## 2. 实现情况

本阶段所有核心目标已全部达成，并在 158 篇真实笔记语料上完成端到端实机验证：

1. **双路召回与融合落地**：后端完成 Lucene 9 适配器与 RRF 融合逻辑，针对查询「挂载 NAS」等用例，成功召回出仅关键词命中的关键切片，双路互补效果明显。
2. **三方数据完全对齐**：全量重建关键词索引实测仅耗时 3.9 秒；MySQL 有效切片（2195 条）、Lucene 索引（2195 条）与 Qdrant 向量点数（2195 个）三方完全一致。
3. **权限判定安全加固**：彻底修复了先前文档设为私有后索引未及时同步导致的潜在泄漏问题，确保公开访问（`scope=public`）下只能检索到公开已发布文档。
4. **后台可视化调试升级**：检索调试页面正式上线「命中来源」、「两路排名」及「融合指标栏」，能够清晰追踪从「召回 30 条 → 融合 20 条 → 返回 8 条」的全过程。

## 3. 核心功能与接口一览

- **管理端混合检索接口**：`POST /api/v1/admin/knowledge/retrieval/search`
  - 新增 `keywordEnabled` 开关：支持临时关闭关键词检索，便于直观对比单路向量与双路混合的效果差异。
  - 响应结果中新增 `matchedBy`（`vector` / `keyword` / `both`）、`rrfScore`、两路独立排名等丰富解释字段。
- **全量重建关键词索引**：`POST /api/v1/admin/knowledge/keyword-index/rebuild`
  - 快速全量刷新本地 Lucene 索引，纯本地运算，不产生外部费用。

---

## 4. 关键规则与运行约束

- **MySQL 权限绝对权威**：向量库和 Lucene 索引中的权限标记仅用于初筛缩小范围；检索结果在组装返回前，系统必须再次读取 MySQL 核验权限，任何已下线或未公开内容都会被无条件拦截。
- **单实例写锁约束**：由于 Lucene 采用进程内嵌入文件存储，本地开发时**不能同时启动两个后端进程**，否则第二个进程会因为获取不到索引写锁（`write.lock`）而启动失败。
